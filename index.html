📚Introduction to Graph Theory

DMS — Unit 5

In Discrete Mathematical Structures, a graph is a mathematical structure used to model relationships between objects. Graphs are one of the most versatile and widely applied topics in computer science and mathematics — from social networks and the internet to compilers and operating systems.

💡 Why is graph traversal important? Many practical problems — finding the shortest route, checking network connectivity, detecting cycles, scheduling tasks — can be solved by systematically visiting every vertex in a graph. BFS and DFS are the two fundamental strategies for doing this.

What is a Graph?

A graph G is defined as an ordered pair G = (V, E) where:

  • V is a non-empty finite set of elements called vertices (or nodes).
  • E is a set of pairs of vertices called edges (or arcs).

Each edge represents a connection or relationship between two vertices. For example, if we model a city road network as a graph, then intersections are vertices and roads are edges.

📖Basic Definitions

Write these in your Assignment Book
Graph
A non-linear mathematical structure consisting of a set of vertices (V) and a set of edges (E) connecting pairs of vertices. Formally: G = (V, E).
Example: G = ({A, B, C}, {(A,B), (B,C)})
Vertex (Node)
A fundamental unit (point) in a graph. Represented visually as a circle. The set of all vertices is denoted V. Each vertex may represent any entity — a city, a person, a computer.
Example: Vertices = {A, B, C, D, E}
Edge (Arc)
A connection between two vertices. An edge {u, v} (undirected) or (u, v) (directed) indicates that vertex u and vertex v are related. Represented as a line between two circles.
Example: Edge (A, B) connects vertices A and B
Adjacent Vertices
Two vertices are adjacent (or neighbours) if there is an edge directly connecting them. Vertex u is adjacent to vertex v if edge (u,v) ∈ E.
Example: A is adjacent to B if edge (A,B) exists
Degree of a Vertex
The degree of a vertex v, written deg(v), is the number of edges incident to it (the number of neighbours it has). In a directed graph, in-degree counts incoming edges and out-degree counts outgoing edges.
Example: If vertex A connects to B, C, D → deg(A) = 3
Walk
A walk is a sequence of vertices v₁, v₂, …, vₖ where consecutive vertices are connected by edges. Vertices and edges may be repeated in a walk.
Example: A → B → C → B → D is a walk
Path
A path is a walk in which no vertex is repeated. A simple path visits each vertex at most once. The length of a path is the number of edges in it.
Example: A → B → C → D is a path (no repeated vertices)
Cycle
A cycle is a closed path — a path that begins and ends at the same vertex, with no other repeated vertices. A graph with at least one cycle is called a cyclic graph.
Example: A → B → C → A is a cycle
Connected Graph
An undirected graph is connected if there exists a path between every pair of vertices. If some vertices cannot reach others, the graph is disconnected and has multiple connected components.
Example: All vertices A–E reachable from any vertex → connected
Directed Graph (Digraph)
A graph where every edge has a specific direction. An edge (u → v) goes from u to v but not necessarily from v to u. Used to model one-way relationships such as web links or task dependencies.
Example: A → B means you can go from A to B, but not B to A
Undirected Graph
A graph where edges have no direction — the edge {u, v} is the same as {v, u}. Movement is possible in both directions. Used to model symmetric relationships like friendships or two-way roads.
Example: A—B means travel is possible from A to B and B to A
Subgraph
A graph H = (V', E') is a subgraph of graph G = (V, E) if V' ⊆ V and E' ⊆ E. A subgraph contains some (or all) vertices and edges of the original graph.
Example: Taking only vertices A, B, C and edges between them from G

🌊Breadth First Search (BFS)

Queue · FIFO · Level by Level

Definition

Breadth First Search (BFS) is a graph traversal algorithm that visits vertices level by level, starting from a selected source vertex. It first explores all vertices at distance 1 from the source, then all vertices at distance 2, and so on. BFS uses a Queue (First In, First Out) data structure.

Basic Idea

Imagine standing at vertex A and wanting to visit every reachable vertex exactly once. BFS explores like expanding rings of water — it visits all immediate neighbours first (Level 1), then their neighbours (Level 2), continuing outward until all reachable vertices are visited.

🌊 Visual analogy: Like ripples spreading on water — each ring represents one level of BFS traversal. The queue ensures we finish processing one ring before starting the next.

The Queue (FIFO) Concept

BFS maintains a queue — a linear data structure where items are added at the rear and removed from the front (First In, First Out). When we discover a vertex's neighbour, we enqueue (add to rear) it. When we process a vertex, we dequeue (remove from front) it. This FIFO property ensures vertices are visited in the order they were discovered, producing level-by-level traversal.

FRONT (Dequeue) ➔
A
B
C
D
➔ REAR (Enqueue)

BFS Algorithm (Step-by-Step)

  1. Select the starting vertex s. Mark it as visited.
  2. Enqueue s into the Queue.
  3. While the Queue is not empty:
    • Dequeue a vertex u from the front.
    • Process u (add to traversal order).
    • For each unvisited neighbour v of u:
      • Mark v as visited.
      • Enqueue v at the rear.
  4. Repeat until Queue is empty. Traversal is complete.
Time Complexity
O(V + E)
Each vertex is enqueued once O(V). Each edge is examined once during adjacency list scanning O(E).
Space Complexity
O(V)
The queue holds at most all vertices at a given level. The visited array also requires O(V) space.
Shortest Path
✓ Yes
BFS guarantees the shortest path (fewest edges) in an unweighted graph due to level-by-level exploration.

Applications of BFS

🗺️
Shortest Path Finding
Finding shortest route in unweighted road networks or mazes.
👥
Social Networks
Finding degrees of separation between people (e.g. LinkedIn, Facebook friend suggestions).
🌐
Web Crawlers
Search engines use BFS to index web pages level by level from a starting URL.
📡
Network Broadcasting
Broadcasting packets to all nodes in a network using minimum hops.
🎮
Game AI
Finding the nearest item, enemy, or exit in grid-based game maps.
🔌
Connectivity Check
Checking whether all vertices in a graph are reachable from a source.

🌲Depth First Search (DFS)

Stack · LIFO · Backtracking

Definition

Depth First Search (DFS) is a graph traversal algorithm that explores as deep as possible along each branch before backtracking. Starting from a source vertex, DFS dives along one path until it reaches a dead end (a vertex with no unvisited neighbours), then backtracks to find another unexplored path. DFS uses a Stack (Last In, First Out) — either explicitly or via recursion.

Basic Idea

DFS behaves like exploring a maze — you go as far as possible in one direction. When you hit a dead end, you retrace your steps (backtrack) to the most recent junction and try a different path. You continue until every reachable vertex is visited.

🌲 Visual analogy: Like exploring a deep cave system — you enter one tunnel completely before trying another. The call stack (recursion) remembers where you came from so you can backtrack.

The Stack (LIFO) and Recursion Concept

DFS uses a stack — items are added (pushed) and removed (popped) from the same end (Last In, First Out). In recursive DFS, the program's own call stack acts as the stack. When we visit vertex u, we recursively call DFS on its unvisited neighbours. Backtracking occurs naturally when the recursive call returns.

TOP (Push / Pop) ⬆⬇
C (deepest)
B
A (root)
BOTTOM

DFS Algorithm — Recursive

  1. Mark the starting vertex s as visited. Process it.
  2. For each unvisited neighbour v of s:
    • Recursively call DFS on v.
  3. When no unvisited neighbours remain, backtrack to the previous vertex.
  4. Repeat until all reachable vertices are visited.
Time Complexity
O(V + E)
Each vertex is visited once O(V). Each edge is examined during adjacency list traversal O(E).
Space Complexity
O(h)
The recursion stack depth is proportional to the maximum depth h of the DFS tree, at most O(V).
Shortest Path
✗ Not Guaranteed
DFS does not guarantee finding the shortest path — it follows one path deeply before trying others.

Applications of DFS

📋
Topological Sorting
Ordering tasks or build steps based on dependencies (used in compilers and project management).
🔍
Cycle Detection
Finding cycles in directed graphs — used for deadlock detection in operating systems.
🧩
Maze Solving & Puzzles
Solving mazes, N-Queens problem, Sudoku — naturally fits the backtracking approach of DFS.
🌳
Finding Spanning Trees
DFS generates a DFS spanning tree of the graph during traversal.
🤖
AI & Game Trees
Minimax algorithm in game AI uses DFS to explore game states recursively.
🔗
Strongly Connected Components
Tarjan's and Kosaraju's algorithms use DFS to find SCCs in directed graphs.

⚖️ Key takeaway: Both BFS and DFS have the same time complexity O(V+E). The difference is in order of exploration, memory usage, and which problems they are best suited for.

Example 1 BFS on a Connected Undirected Graph — Starting from Vertex A

The Graph:

V = {A,B,C,D,E}  |  Edges: A–B, A–D, B–C, B–E, D–E

Adjacency List:
A: [B, D]  |  B: [A, C, E]  |  C: [B]
D: [A, E]  |  E: [B, D]

BFS Step-by-Step Trace (Start = A):

StepActionQueue AfterVisited
0Start at A. Enqueue A. Mark visited.[A]{A}
1Dequeue A. Examine neighbours B, D. Enqueue B, D.[B, D]{A, B, D}
2Dequeue B. Neighbours A(visited), C, E. Enqueue C, E.[D, C, E]{A, B, D, C, E}
3Dequeue D. Neighbours A(visited), E(visited). Nothing enqueued.[C, E]{A, B, D, C, E}
4Dequeue C. Neighbour B(visited). Nothing enqueued.[E]{A, B, D, C, E}
5Dequeue E. Neighbours B, D (all visited). Queue empty.[ ]{A, B, D, C, E}
BFS Traversal Order: A → B → D → C → E
Why this order? BFS visits all Level 1 neighbours of A (which are B and D) before going to Level 2 (C and E, which are neighbours of B). D's neighbours are all already visited, so it adds nothing new. C and E are reached last.
Example 2 DFS on the Same Graph — Starting from Vertex A

Same Graph (as Example 1)

V = {A,B,C,D,E}  |  Edges: A–B, A–D, B–C, B–E, D–E

Adjacency list (alphabetical order assumed):
A: [B, D]  |  B: [A, C, E]  |  C: [B]
D: [A, E]  |  E: [B, D]

⚡ Notice how DFS produces a completely different order than BFS on the same graph!

DFS Step-by-Step Trace (Recursive, Start = A):

StepActionCall StackVisited
1Call DFS(A). Visit A.[DFS(A)]{A}
2A's first unvisited neighbour: B. Call DFS(B). Visit B.[DFS(A), DFS(B)]{A, B}
3B's first unvisited neighbour: C. Call DFS(C). Visit C.[DFS(A), DFS(B), DFS(C)]{A, B, C}
4C's neighbour B is visited. Dead end! Backtrack to B.[DFS(A), DFS(B)]{A, B, C}
5B's next unvisited neighbour: E. Call DFS(E). Visit E.[DFS(A), DFS(B), DFS(E)]{A, B, C, E}
6E's neighbours B, D. D is unvisited. Call DFS(D). Visit D.[DFS(A), DFS(B), DFS(E), DFS(D)]{A, B, C, E, D}
7D's neighbours all visited. Backtrack all the way. Done.[ ]{A, B, C, E, D}
DFS Traversal Order: A → B → C → E → D
Why different from BFS? DFS dives deep into B's subtree (C, then E, then D through E) before returning to A's other neighbour D. BFS would have visited D at Level 1 (right after B), but DFS only reaches D much later via the path A→B→E→D.

Example 4 BFS on a Disconnected Graph — Two Components

Graph has two disconnected components: Component 1 = {A, B, C} and Component 2 = {D, E, F}. Running BFS from vertex A.

BFS from Vertex A — What happens?

StepActionQueueVisited

BFS
Objective: To understand the step-by-step working of the Breadth First Search algorithm by manually tracing it on a given graph.
Given Graph:
Vertices: {1, 2, 3, 4, 5, 6}
Edges: (1,2), (1,3), (2,4), (2,5), (3,6), (4,5)

Adjacency List: 1:[2,3], 2:[1,4,5], 3:[1,6], 4:[2,5], 5:[2,4], 6:[3]

BFS Queue trace:
Enqueue 1 → Queue: [1]
Dequeue 1 → Visit 1. Enqueue 2, 3 → Queue: [2, 3]

Perform DFS Manually on the Same Graph

DFS
Objective: To understand the step-by-step working of the Depth First Search algorithm and observe the difference from BFS on the same graph.
Given: Same graph from Activity 1. Vertices: {1,2,3,4,5,6}. Edges: (1,2),(1,3),(2,4),(2,5),(3,6),(4,5).

  1. Use the same graph drawn in Activity 1.
  2. Start DFS from vertex 1 using recursive approach.
  3. At each step: visit the current vertex, then recursively explore its first unvisited neighbour.
  4. When you reach a dead end (no unvisited neighbours), backtrack.
  5. Record the call stack at each step and the DFS traversal order.

✏️ Try Solving Right Here:
DFS Recursive Trace (neighbours in ascending order):
DFS(1) → visit 1. Call DFS(2).
DFS(2) → visit 2. Call DFS(4).
DFS(4) → visit 4. Neighbour 5 unvisited. Call DFS(5).
DFS(5) → visit 5. Neighbours 2(V), 4(V). Dead end. Return to 4.
Back at 4 → No more unvisited. Return to 2.
Back at 2 → 5 already visited. Return to 1.
Back at 1 → Call DFS(3).
DFS(3) → visit 3. Call DFS(6).
DFS(6) → visit 6. Dead end. Return to 3. Return to 1. Done.

DFS Traversal Order: 1 → 2 → 4 → 5 → 3 → 6

Activity 5

Compare BFS and DFS Traversal Orders

Comparison
Objective: To compare and contrast BFS and DFS traversal orders on the same graph and identify cases where they produce different results.
Given Graph: A binary tree-like graph with vertices {A, B, C, D, E, F, G}.
A connects to B, C. B connects to D, E. C connects to F, G.
Procedure:
  1. Draw the graph.
  2. Perform BFS from vertex A. Record full trace and order.
  3. Perform DFS from vertex A. Record full trace and order.
  4. Write both orders side by side and underline where they differ.
  5. Explain why they differ — relate to the queue vs stack data structure used.
  6. Write a conclusion comparing BFS and DFS.
Expected Observation: BFS produces level-order A→B→C→D→E→F→G. DFS produces pre-order A→B→D→E→C→F→G. The difference begins at the 3rd vertex.
✏️ Try Solving Right Here:
BFS Order: A → B → C → D → E → F → G (Level-order traversal)
DFS Order: A → B → D → E → C → F → G (Pre-order traversal)

Comparison:
Position 3 — BFS: C (Level 1 sibling of B), DFS: D (child of B, goes deeper first)
Position 4 — BFS: D (Level 2), DFS: E (sibling of D, still in B's subtree)
Position 5 — BFS: E, DFS: C (only now does DFS come back to A's second child C)

Reason for difference: BFS uses a Queue (FIFO) so B and C are both processed at Level 1 before going to Level 2. DFS uses recursion (Stack/LIFO) so it fully explores B's subtree (D, E) before coming back to C.

Conclusion: BFS and DFS produce identical traversal only when the graph is a simple path (linear). For branching graphs, they differ because BFS is "wide-first" and DFS is "deep-first".

Q8Analysis

For Q6 and Q7, compare the BFS order (A→B→C→D→E) with the DFS order. At which positions do they differ? Explain why.

BFS: A → B → C → D → E
DFS: A → B → D → C → E

They differ at position 3: BFS gives C (Level 1 neighbour of A), DFS gives D (goes deeper through B→D before returning to A's other neighbour C).

Reason: BFS uses a Queue — after visiting B, it enqueues C and then processes C before going deeper to D. DFS uses recursion (Stack) — after visiting B, it immediately dives to D without returning to C first.

Level 3Advanced — Analysis & Applications
Q10Advanced

Prove or disprove: "BFS always finds the shortest path between two vertices in an unweighted graph." Provide reasoning with a supporting example.

True — BFS finds a shortest (fewest-edge) path in an unweighted graph.

Proof idea: BFS visits vertices in non-decreasing order of distance from the source. All vertices at distance d are dequeued before any at distance d+1, so the first time a vertex v is discovered, it is reached by a path with the fewest possible edges.

Example: edges A–B, B–D, A–C, C–E, E–D. From A, BFS discovers B and C (distance 1), then D via B (distance 2). The longer route A→C→E→D (3 edges) is never used for D.

DFS does not guarantee this: it could reach D first through A→C→E→D.
Q11Advanced

Given a disconnected graph with 3 components: {1,2,3}, {4,5}, {6}. Write the complete modified BFS/DFS algorithm that visits ALL vertices across all components.

Modified BFS for disconnected graphs:
mark all vertices as UNVISITED
for each vertex v in V:
    if v is UNVISITED:

Result: Component 1: BFS(1) → 1,2,3; Component 2: BFS(4) → 4,5; Component 3: BFS(6) → 6

Full order: 1 → 2 → 3 → 4 → 5 → 6
This gives us the number of connected components = number of times BFS/DFS is restarted = 3.
Q12Application

A network of computers: {A,B,C,D,E}. Links: A-B, A-C, B-D, C-E. Computer A sends a broadcast message. Using BFS, determine in what order computers receive the message, and how many hops each computer is from A.

BFS from A (source):

Level 2 (2 hops): D (from B), E (from C)

Q13Advanced

A graph G is given with V={1,2,3,4,5,6,7}. For this graph: BFS from vertex 1 gives order 1,2,3,4,5,6,7. DFS from vertex 1 gives order 1,2,4,5,3,6,7. Reconstruct a possible edge set E for this graph. (There may be multiple valid answers.)

Q14Comparison

Explain when you would choose BFS over DFS and vice versa. Give a practical example problem for each choice and justify your answer.

Choose BFS when:
• You need the shortest path in an unweighted graph.
• The target vertex is likely close to the source.
• You need level-order or layer-by-layer processing.
Example: Finding the fewest number of flights between two cities (unweighted graph).

Choose DFS when:
• You need to explore all possibilities exhaustively (e.g., puzzle solving).
• Memory is limited (DFS uses O(h) vs BFS's O(V)).
• The problem involves backtracking, topological sorting, or cycle detection.
Example: Solving a maze — DFS naturally backtracks when it hits a dead end, mimicking how a person would navigate a maze.
Q15Theory

A BFS tree is formed when BFS traverses a graph. What is a BFS tree? What is the significance of the levels in a BFS tree? How does the BFS tree relate to shortest paths?

BFS Tree: A BFS tree is a spanning tree of the graph formed by the tree edges (edges that lead to the discovery of new vertices) during BFS traversal. Every vertex appears exactly once in the BFS tree.

Significance of levels: The level of a vertex v in the BFS tree = the shortest distance (fewest edges) from the source vertex s to v. All vertices at the same level are the same distance from the source.

Relationship to shortest paths: The path from the root (source) to any vertex v in the BFS tree IS the shortest path in the original unweighted graph. This is the key property that makes BFS the algorithm of choice for shortest path problems in unweighted graphs.

🔗Connected Components

Undirected Graphs

Definition

A connected component of an undirected graph is a maximal set of vertices such that there is a path between every pair of vertices in the set. A graph may have one component (connected) or multiple components (disconnected).

🔗 Key idea: If you start BFS or DFS from any vertex, you can only reach vertices in the same component. To find all components, iterate over every vertex — whenever you encounter an unvisited vertex, start a new traversal and assign a new component ID.

Theory & Definitions

Connected Graph
An undirected graph where there exists a path between every pair of vertices. Equivalently, it has exactly one connected component.
Disconnected Graph
A graph with two or more connected components. Some pairs of vertices have no path between them.
Isolated Vertex
A vertex with degree 0 (no edges). An isolated vertex forms its own connected component of size 1.
Maximal Connected Subgraph
A connected component is maximal — no additional vertex can be added while keeping the subgraph connected.

Algorithm — Finding Connected Components

componentCount = 0 for each vertex v in G: if v is UNVISITED: componentCount = componentCount + 1 explore(v, componentCount) explore(v, componentId): mark v as VISITED assign componentId to v for each neighbour u of v: if u is UNVISITED: explore(u, componentId)

The explore function can use either BFS (queue) or DFS (recursion/stack). Both produce correct components.

📍Dijkstra's Shortest Path Algorithm

Weighted Graphs · Priority Queue

Definition & Purpose

Dijkstra's algorithm finds the shortest path from a single source vertex to all other vertices in a graph with non-negative edge weights. It was conceived by Edsger W. Dijkstra in 1956.

⚠️ Important: Dijkstra's algorithm does not work correctly with negative edge weights. For graphs with negative weights, use the Bellman–Ford algorithm instead.

Key Concepts

Weighted Graph
A graph where each edge has a numerical value (weight) representing cost, distance, or time. Edge (u, v) has weight w(u,v) ≥ 0.
Tentative Distance
The current best-known distance from the source to a vertex. Initially ∞ for all vertices except the source (which is 0). Updated via edge relaxation.
Edge Relaxation
Checking if the path through the current vertex is shorter: if dist[u] + w(u,v) < dist[v], update dist[v] and set prev[v] = u.
Priority Queue (Min-Heap)
A data structure that always extracts the element with the smallest key. Used to select the unprocessed vertex with the smallest tentative distance.
Predecessor / Parent
For each vertex v, prev[v] records which vertex led to the shortest known path. Used to reconstruct the actual shortest path.
Shortest-Path Tree
The tree formed by the predecessor edges. It contains the shortest path from the source to every reachable vertex.

Algorithm (Pseudocode)

DIJKSTRA(G, source): for each vertex v in G: dist[v] = ∞ prev[v] = undefined processed[v] = false dist[source] = 0 PQ = MinPriorityQueue() PQ.insert(source, 0) while PQ is not empty: u = PQ.extractMin() if processed[u]: continue // skip stale entries processed[u] = true for each neighbour v of u with weight w: alt = dist[u] + w if alt < dist[v]: // relaxation dist[v] = alt prev[v] = u PQ.insert(v, alt) return dist[], prev[]

Step-by-Step Walkthrough

  1. Set source distance to 0, all others to ∞.
  2. Insert source into the priority queue with priority 0.
  3. Extract the vertex u with the smallest distance from the queue.
  4. If u is already processed, skip it (stale entry).
  5. Mark u as processed (its distance is now finalized).
  6. For each neighbour v of u: compute alternative distance = dist[u] + weight(u,v).
  7. If alternative < dist[v], relax the edge: update dist[v] and prev[v].
  8. Insert v with new distance into the priority queue.
  9. Repeat steps 3–8 until the queue is empty.
  10. Reconstruct shortest paths using the prev[] array.

1BFS.java — Breadth-First Search

Queue-based

Uses ArrayDeque as a queue. Handles disconnected graphs by iterating over all vertices.

import java.util.*;

public class BFS {
    // Adjacency list representation
    private Map<String, List<String>> adj = new LinkedHashMap<>();

    public void addVertex(String v) {
        adj.putIfAbsent(v, new ArrayList<>());
    }

    public void addEdge(String u, String v) {
        addVertex(u);
        addVertex(v);
        adj.get(u).add(v);
        adj.get(v).add(u); // undirected
    }

    /**
     * BFS from a single source vertex.
     * Returns the traversal order.
     */
    public List<String> bfs(String source) {
        List<String> order = new ArrayList<>();
        Set<String> visited = new HashSet<>();
        Deque<String> queue = new ArrayDeque<>();

        visited.add(source);
        queue.add(source);

        while (!queue.isEmpty()) {
            String u = queue.poll(); // dequeue front
            order.add(u);

            // Sort neighbours for deterministic order
            List<String> neighbours = new ArrayList<>(adj.get(u));
            Collections.sort(neighbours);

            for (String v : neighbours) {
                if (!visited.contains(v)) {
                    visited.add(v);
                    queue.add(v); // enqueue at rear
                }
            }
        }
        return order;
    }

    /**
     * BFS across all components of a disconnected graph.
     */
    public List<String> bfsAll() {
        List<String> order = new ArrayList<>();
        Set<String> visited = new HashSet<>();

        for (String v : adj.keySet()) {
            if (!visited.contains(v)) {
                System.out.println("Starting new BFS from: " + v);
                Deque<String> queue = new ArrayDeque<>();
                visited.add(v);
                queue.add(v);
                while (!queue.isEmpty()) {
                    String u = queue.poll();
                    order.add(u);
                    List<String> nbrs = new ArrayList<>(adj.get(u));
                    Collections.sort(nbrs);
                    for (String w : nbrs) {
                        if (!visited.contains(w)) {
                            visited.add(w);
                            queue.add(w);
                        }
                    }
                }
            }
        }
        return order;
    }

    public static void main(String[] args) {
        BFS g = new BFS();
        // Sample graph: A-B, A-D, B-C, B-E, D-E
        g.addEdge("A", "B");
        g.addEdge("A", "D");
        g.addEdge("B", "C");
        g.addEdge("B", "E");
        g.addEdge("D", "E");

        System.out.println("=== BFS from A ===");
        System.out.println("Traversal: " + g.bfs("A"));
        // Expected: [A, B, D, C, E]

        System.out.println("\n=== BFS All Components ===");
        System.out.println("Full traversal: " + g.bfsAll());
    }
}
✅Expected Output: BFS from A → [A, B, D, C, E]. Level 1: {B, D}. Level 2: {C, E}.

2DFS.java — Depth-First Search

Recursive + Iterative

Includes both recursive and iterative (explicit stack using ArrayDeque) implementations.

import java.util.*;

public class DFS {
    private Map<String, List<String>> adj = new LinkedHashMap<>();

    public void addVertex(String v) {
        adj.putIfAbsent(v, new ArrayList<>());
    }

    public void addEdge(String u, String v) {
        addVertex(u);
        addVertex(v);
        adj.get(u).add(v);
        adj.get(v).add(u); // undirected
    }

    // ==================== RECURSIVE DFS ====================
    public List<String> dfsRecursive(String source) {
        List<String> order = new ArrayList<>();
        Set<String> visited = new HashSet<>();
        dfsHelper(source, visited, order);
        return order;
    }

    private void dfsHelper(String u, Set<String> visited, List<String> order) {
        visited.add(u);
        order.add(u);
        System.out.println("  Visit " + u + " | Stack depth: " + order.size());

        // Sort for deterministic neighbour ordering
        List<String> neighbours = new ArrayList<>(adj.get(u));
        Collections.sort(neighbours);

        for (String v : neighbours) {
            if (!visited.contains(v)) {
                System.out.println("  " + u + " → " + v + " (recurse)");
                dfsHelper(v, visited, order);
                System.out.println("  Backtrack to " + u);
            }
        }
    }

    // ==================== ITERATIVE DFS ====================
    public List<String> dfsIterative(String source) {
        List<String> order = new ArrayList<>();
        Set<String> visited = new HashSet<>();
        Deque<String> stack = new ArrayDeque<>();

        stack.push(source);

        while (!stack.isEmpty()) {
            String u = stack.pop();
            if (visited.contains(u)) continue;
            visited.add(u);
            order.add(u);

            // Push neighbours in reverse order so smallest is processed first
            List<String> neighbours = new ArrayList<>(adj.get(u));
            Collections.sort(neighbours, Collections.reverseOrder());

            for (String v : neighbours) {
                if (!visited.contains(v)) {
                    stack.push(v);
                }
            }
        }
        return order;
    }

    public static void main(String[] args) {
        DFS g = new DFS();
        g.addEdge("A", "B");
        g.addEdge("A", "D");
        g.addEdge("B", "C");
        g.addEdge("B", "E");
        g.addEdge("D", "E");

        System.out.println("=== Recursive DFS from A ===");
        System.out.println("Order: " + g.dfsRecursive("A"));
        // Expected: [A, B, C, E, D]

        System.out.println("\n=== Iterative DFS from A ===");
        System.out.println("Order: " + g.dfsIterative("A"));
        // Expected: [A, B, C, E, D]
    }
}
📝Iterative DFS pushes neighbours in reverse sorted order so the smallest label is on top of the stack and gets processed first — matching the recursive version.

3ConnectedComponents.java

DFS-based Detection

Finds and labels all connected components. Supports isolated vertices.

import java.util.*;

public class ConnectedComponents {
    private Map<String, List<String>> adj = new LinkedHashMap<>();

    public void addVertex(String v) {
        adj.putIfAbsent(v, new ArrayList<>());
    }

    public void addEdge(String u, String v) {
        addVertex(u);
        addVertex(v);
        adj.get(u).add(v);
        adj.get(v).add(u);
    }

    /**
     * Finds all connected components using DFS.
     * Returns a map: vertex → component number (1-based).
     */
    public Map<String, Integer> findComponents() {
        Map<String, Integer> componentId = new LinkedHashMap<>();
        int count = 0;

        for (String v : adj.keySet()) {
            if (!componentId.containsKey(v)) {
                count++;
                // DFS to mark all vertices in this component
                Deque<String> stack = new ArrayDeque<>();
                stack.push(v);
                while (!stack.isEmpty()) {
                    String u = stack.pop();
                    if (componentId.containsKey(u)) continue;
                    componentId.put(u, count);
                    for (String w : adj.get(u)) {
                        if (!componentId.containsKey(w)) {
                            stack.push(w);
                        }
                    }
                }
            }
        }

        System.out.println("Total connected components: " + count);
        return componentId;
    }

    public static void main(String[] args) {
        ConnectedComponents g = new ConnectedComponents();

        // Component 1: A-B-C
        g.addEdge("A", "B");
        g.addEdge("B", "C");
        g.addEdge("A", "C");

        // Component 2: D-E
        g.addEdge("D", "E");

        // Component 3: F (isolated)
        g.addVertex("F");

        // Component 4: G-H
        g.addEdge("G", "H");

        System.out.println("=== Connected Components ===");
        Map<String, Integer> result = g.findComponents();

        // Group by component
        Map<Integer, List<String>> groups = new TreeMap<>();
        for (Map.Entry<String, Integer> e : result.entrySet()) {
            groups.computeIfAbsent(e.getValue(), k -> new ArrayList<>()).add(e.getKey());
        }

        for (Map.Entry<Integer, List<String>> e : groups.entrySet()) {
            System.out.println("Component " + e.getKey() + ": " + e.getValue());
        }
        // Expected:
        // Component 1: [A, B, C]
        // Component 2: [D, E]
        // Component 3: [F]
        // Component 4: [G, H]
    }
}

4Dijkstra.java — Shortest Path

PriorityQueue-based

Uses Java's PriorityQueue with a custom comparator. Includes negative-weight validation and path reconstruction.

import java.util.*;

public class Dijkstra {

    // Edge representation
    static class Edge {
        String target;
        int weight;
        Edge(String target, int weight) {
            this.target = target;
            this.weight = weight;
        }
    }

    private Map<String, List<Edge>> adj = new LinkedHashMap<>();

    public void addVertex(String v) {
        adj.putIfAbsent(v, new ArrayList<>());
    }

    public void addEdge(String u, String v, int weight) {
        if (weight < 0) {
            throw new IllegalArgumentException(
                "Negative weight " + weight + " on edge " + u + "-" + v +
                ". Dijkstra requires non-negative weights.");
        }
        addVertex(u);
        addVertex(v);
        adj.get(u).add(new Edge(v, weight));
        adj.get(v).add(new Edge(u, weight)); // undirected
    }

    /**
     * Dijkstra's shortest path from source to all vertices.
     */
    public void dijkstra(String source) {
        Map<String, Integer> dist = new HashMap<>();
        Map<String, String> prev = new HashMap<>();
        Set<String> processed = new HashSet<>();

        // Initialize distances
        for (String v : adj.keySet()) {
            dist.put(v, Integer.MAX_VALUE);
            prev.put(v, null);
        }
        dist.put(source, 0);

        // Min-heap: [distance, vertex]
        PriorityQueue<int[]> pq = new PriorityQueue<>(
            Comparator.comparingInt(a -> a[0]));
        Map<String, Integer> nameToIndex = new HashMap<>();
        List<String> names = new ArrayList<>(adj.keySet());
        for (int i = 0; i < names.size(); i++)
            nameToIndex.put(names.get(i), i);

        pq.add(new int[]{0, nameToIndex.get(source)});

        while (!pq.isEmpty()) {
            int[] top = pq.poll();
            String u = names.get(top[1]);

            if (processed.contains(u)) continue; // skip stale
            processed.add(u);

            System.out.println("Process " + u + " (dist=" + dist.get(u) + ")");

            for (Edge e : adj.get(u)) {
                if (processed.contains(e.target)) continue;
                int alt = dist.get(u) + e.weight;
                if (alt < dist.get(e.target)) {
                    dist.put(e.target, alt);
                    prev.put(e.target, u);
                    pq.add(new int[]{alt, nameToIndex.get(e.target)});
                    System.out.println("  Relax " + u + "->" + e.target +
                        " (new dist=" + alt + ")");
                }
            }
        }

        // Print results
        System.out.println("\n--- Shortest Distances from " + source + " ---");
        for (String v : adj.keySet()) {
            String d = dist.get(v) == Integer.MAX_VALUE ? "∞ (unreachable)" :
                       String.valueOf(dist.get(v));
            System.out.println("  " + v + ": " + d + "  path: " +
                               reconstructPath(prev, source, v));
        }
    }

    private String reconstructPath(Map<String, String> prev,
                                    String source, String target) {
        if (prev.get(target) == null && !target.equals(source))
            return "(no path)";
        List<String> path = new ArrayList<>();
        String cur = target;
        while (cur != null) {
            path.add(cur);
            cur = prev.get(cur);
        }
        Collections.reverse(path);
        return String.join(" → ", path);
    }

    public static void main(String[] args) {
        Dijkstra g = new Dijkstra();

        // Sample weighted graph
        g.addEdge("A", "B", 4);
        g.addEdge("A", "C", 2);
        g.addEdge("B", "C", 1);
        g.addEdge("B", "D", 5);
        g.addEdge("C", "D", 8);
        g.addEdge("C", "E", 10);
        g.addEdge("D", "E", 2);

        // Add isolated vertex to test disconnected handling
        g.addVertex("F");

        System.out.println("=== Dijkstra from A ===\n");
        g.dijkstra("A");

        // Expected shortest distances from A:
        // A: 0     path: A
        // B: 3     path: A → C → B
        // C: 2     path: A → C
        // D: 8     path: A → C → B → D
        // E: 10    path: A → C → B → D → E
        // F: ∞     path: (no path)
    }
}
⚠️The code validates negative weights with an IllegalArgumentException. Dijkstra's algorithm is not correct for negative edge weights.

📊Complexity Analysis — All Algorithms

Time & Space

This section compares the time and space complexity of all four graph algorithms covered in this platform. Complexities assume an adjacency-list representation unless stated otherwise.

Algorithm Main Data Structure Purpose Time Complexity Auxiliary Space
BFS Queue (FIFO) Level-order traversal, shortest path (unweighted) O(V + E) O(V)
DFS Stack / Recursion Depth-first traversal, cycle detection, topological sort O(V + E) O(V)
Connected Components BFS or DFS Identify connected groups in undirected graphs O(V + E) O(V)
Dijkstra (min-heap) Priority Queue Shortest paths with non-negative weights O((V+E) log V) O(V)
Dijkstra (linear) Array scan Shortest paths (dense graphs) O(V²) O(V)
💡 Note: The total storage for all algorithms also includes the graph representation itself, which is O(V + E) for an adjacency list or O(V²) for an adjacency matrix. The "auxiliary space" column counts only the extra storage used by the algorithm (visited arrays, queues, stacks, distance tables).

When to Use Which Algorithm

Use BFS when…
You need the shortest path in an unweighted graph, want to explore level by level, or need to find all vertices at distance k from a source.
Use DFS when…
You need cycle detection, topological sorting, finding connected components, solving puzzles/mazes, or when the graph is very deep and memory is limited.
Use Connected Components when…
You need to identify how many disconnected groups exist, label each group, or check if two vertices are in the same component.
Use Dijkstra when…
You need shortest paths in a weighted graph with non-negative weights. For negative weights, use Bellman–Ford instead.

Why O(V + E)?

BFS, DFS, and connected components all visit each vertex exactly once — O(V). For each vertex, they examine its adjacency list, which in total across all vertices sums to O(E) (since each edge appears in two adjacency lists for undirected graphs). The combined work is therefore O(V + E).

Why O((V+E) log V) for Dijkstra?

Each vertex is extracted from the priority queue at most once — each extraction costs O(log V), giving O(V log V). For each extracted vertex, its outgoing edges are examined; each edge may insert an entry into the queue — costing O(log V) per insertion, summing to O(E log V). The total is O((V + E) log V).

If you use a simple linear scan instead of a heap (scanning all vertices to find the minimum distance), the extraction cost becomes O(V) per iteration, giving O(V²) total — which is actually faster for very dense graphs where E ≈ V².

Common Mistakes

❌
Confusing BFS shortest path with Dijkstra
BFS finds shortest paths only in unweighted graphs. For weighted graphs, you must use Dijkstra.
❌
Forgetting visited check
Without marking vertices as visited, BFS/DFS will loop infinitely in cyclic graphs.
❌
Using Dijkstra with negative weights
Dijkstra can produce incorrect results with negative edge weights. Use Bellman–Ford instead.
❌
Claiming DFS finds shortest paths
DFS does not guarantee shortest paths. It finds a path, but not necessarily the shortest one.

💬Viva Questions & Answers

Exam Preparation

Click any question to reveal the answer. These are commonly asked in viva voce exams for the DMS course.

Q1 — BFS
What data structure does BFS use and why?
BFS uses a Queue (FIFO). The queue ensures vertices are processed in the order they were discovered — first discovered, first processed. This produces level-by-level traversal because all vertices at distance d from the source are enqueued before any vertex at distance d+1.
Q2 — BFS
Does BFS find the shortest path? Under what conditions?
BFS finds the shortest path (minimum number of edges) only in unweighted graphs (or equivalently, where all edge weights are equal). In weighted graphs, BFS does not account for edge weights — Dijkstra's algorithm is needed instead.
Q3 — DFS
What is backtracking in DFS?
Backtracking occurs when DFS reaches a vertex with no unvisited neighbours (a dead end). The algorithm returns to the most recent vertex that still has unexplored neighbours. In recursive DFS, backtracking happens automatically when the recursive function returns. In iterative DFS, it happens when a vertex popped from the stack has already been visited.
Q4 — DFS
What is the difference between recursive and iterative DFS?
Both produce the same type of traversal. Recursive DFS uses the program's call stack implicitly — each recursive call pushes a frame. Iterative DFS uses an explicit stack data structure (e.g., ArrayDeque). Iterative DFS avoids stack overflow for very deep graphs but may visit neighbours in a different order unless carefully managed.
Q5 — General
What is the time complexity of BFS and DFS? Explain why.
Both have O(V + E) time complexity when using an adjacency list. Each vertex is visited exactly once (O(V)). For each vertex, its adjacency list is scanned to find neighbours, and across all vertices the total adjacency list entries sum to O(2E) for undirected graphs — hence O(E). Total: O(V + E).
Q6 — BFS vs DFS
When would you prefer BFS over DFS, and vice versa?
Use BFS when you need shortest paths in unweighted graphs, or when the target is likely close to the source. Use DFS for topological sorting, cycle detection, solving mazes/puzzles, or when the graph is very deep and you want to use less memory (DFS stack depth is bounded by tree height, not tree width).
Q7 — Connected Components
What is a connected component? How do you find all components?
A connected component is a maximal set of vertices such that there is a path between every pair. To find all components: iterate through all vertices. For each unvisited vertex, start a BFS/DFS — all vertices reached belong to the same component. Increment the component counter and repeat until all vertices are visited.
Q8 — Connected Components
Can a single vertex be a connected component?
Yes. An isolated vertex (one with no edges, degree 0) forms its own connected component of size 1. It is trivially connected to itself.
Q9 — Dijkstra
What is edge relaxation in Dijkstra's algorithm?
Edge relaxation checks if a newly discovered path is shorter than the currently known one. For edge (u, v) with weight w: if dist[u] + w < dist[v], we update dist[v] = dist[u] + w and set prev[v] = u. The term "relaxation" comes from relaxing (loosening) the upper bound on the shortest distance.
Q10 — Dijkstra
Why doesn't Dijkstra work with negative edge weights?
Dijkstra processes each vertex exactly once and assumes that once a vertex is marked as "processed," its distance is final. With negative weights, a later path through a negative-weight edge could produce a shorter distance to an already-processed vertex. The greedy assumption breaks. Use Bellman–Ford for negative weights.
Q11 — Dijkstra
How do you reconstruct the shortest path in Dijkstra?
Maintain a prev[] (predecessor) array. When a shorter path to vertex v is found through u, set prev[v] = u. After the algorithm completes, trace backwards from the destination: target → prev[target] → prev[prev[target]] → … → source. Reverse this sequence to get the path from source to target.
Q12 — General
What is an adjacency list? Why is it preferred over an adjacency matrix?
An adjacency list stores, for each vertex, a list of its neighbours. It uses O(V + E) space. An adjacency matrix uses O(V²) space. For sparse graphs (E ≪ V²), the list is more space-efficient. Algorithms like BFS and DFS also run in O(V + E) with lists, vs O(V²) with matrices (since they must scan an entire row to find neighbours).
Q13 — General
What is a spanning tree?
A spanning tree of a connected graph G is a subgraph that includes all vertices of G and is a tree (connected, acyclic). BFS produces a BFS spanning tree (edges used to discover new vertices). DFS produces a DFS spanning tree. Both spanning trees have exactly V−1 edges.
Q14 — General
What happens if you run BFS/DFS on a disconnected graph?
A single BFS or DFS from one vertex can only reach vertices in the same connected component. Vertices in other components remain unvisited. To visit all vertices, you must restart the traversal from each unvisited vertex, effectively producing a BFS/DFS forest (one tree per component).
Q15 — Dijkstra
What is the complexity of Dijkstra with a binary heap vs a simple array?
With a binary min-heap: O((V + E) log V) — each extract-min and decrease-key operation costs O(log V). With a simple array (linear scan for minimum): O(V²) — each of V iterations scans V vertices. For sparse graphs (E ≈ V), the heap is faster. For dense graphs (E ≈ V²), the array can be faster since the heap operations have higher constants.
Q16 — General
What is a cycle in a graph? How can you detect it?
A cycle is a path that starts and ends at the same vertex with no repeated edges or intermediate vertices. Detection: In an undirected graph, DFS can detect a cycle if it encounters a visited vertex that is not the parent of the current vertex. In a directed graph, DFS detects a cycle by finding a back edge (an edge to a vertex currently on the recursion stack).
Q17 — General
What is the Handshaking Lemma?
The Handshaking Lemma states that the sum of degrees of all vertices in an undirected graph equals twice the number of edges: Σ deg(v) = 2|E|. This is because each edge contributes exactly 1 to the degree of each of its two endpoints. A corollary: the number of vertices with odd degree is always even.
Q18 — BFS
What is a BFS spanning tree?
The edges used to discover new vertices during BFS form a BFS spanning tree. These are called "tree edges." In this tree, the depth of each vertex equals its shortest distance (number of edges) from the source. Non-tree edges (cross edges) connect vertices at the same level or adjacent levels.
Q19 — DFS
Name three applications of DFS.
1. Topological sorting of a directed acyclic graph (DAG). 2. Cycle detection in both directed and undirected graphs. 3. Finding strongly connected components using Tarjan's or Kosaraju's algorithm. Other applications: maze solving, finding articulation points and bridges, generating spanning trees.
Q20 — Dijkstra
What is a shortest-path tree?
The shortest-path tree (SPT) is the tree rooted at the source vertex, formed by the predecessor edges prev[v]. For each vertex v, the unique path from source to v in the SPT is the shortest path in the original graph. The SPT has V−1 edges (for V−1 reachable vertices plus the root).

Graph traversal is a fundamental concept in computer science and discrete mathematics. Through this study, the following key points were understood and demonstrated:

1
What Graph Traversal Means: Graph traversal is the systematic process of visiting every vertex in a graph exactly once, following the edges. It is the foundation of nearly all graph algorithms in computer science.
2
What BFS teaches us: BFS uses a Queue (FIFO) and explores vertices level by level. It is guaranteed to find the shortest path in unweighted graphs and is ideal when the target is likely close to the source.
3
What DFS teaches us: DFS uses a Stack or recursion and explores as deep as possible along one path before backtracking. It is ideal for exhaustive search problems like maze solving, cycle detection, and topological sorting.
4
Key Difference: BFS is "wide first" (explores all neighbours at current distance before going deeper) while DFS is "deep first" (follows one path completely before trying alternatives). Both have time complexity O(V+E).
5
Importance of Interactive Visualization: Using step-by-step animation to trace BFS queue states and DFS call stack states greatly helps in understanding why the algorithms work the way they do — which is difficult to grasp from the written steps alone.
6
Disconnected Graphs: A single BFS or DFS traversal starting from one vertex can only visit vertices in the same connected component. Disconnected graphs require restarting the traversal from each unvisited vertex.
